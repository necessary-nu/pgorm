# Generating entities

A database that already exists has its schema written down as DDL: the
`CREATE TABLE` and `CREATE TYPE` statements that make it. `pgorm-codegen`
reads that DDL and writes the entity modules that describe it, one file per
table, in the form [Entities](crate::guide::entities) teaches. It is a library with
no command-line tool: a build script or a small binary of your own calls it
and writes the files where the program keeps its entities.

The DDL is read with libpg_query, PostgreSQL's own parser, so it is read as
PostgreSQL 18 reads it. Nothing connects to a database.

## Adding the crate

`pgorm-codegen` lives in pgorm's repository and is depended on the same way
as pgorm. Generation happens at build time, so it is usually a
build-dependency or a dependency of a small tool:

```toml
[build-dependencies]
pgorm-codegen = { git = "https://github.com/necessary-nu/pgorm" }
```

## From DDL to entity files

`entities_from_sql` takes the DDL text and an `EntityWriterOptions`, and
returns a `WriterOutput` whose `files` each hold a file `name` and its
`content`. Here is the bakery's `bakery` and `cake` tables, with the cake's
flavor enum:

```rust
use pgorm_codegen::{EntityWriterOptions, entities_from_sql};

const DDL: &str = r#"
CREATE TYPE flavor AS ENUM ('chocolate', 'vanilla', 'lemon', 'carrot');

CREATE TABLE bakery (
    id serial PRIMARY KEY,
    name varchar NOT NULL,
    city varchar NOT NULL
);

CREATE TABLE cake (
    id serial PRIMARY KEY,
    name varchar NOT NULL,
    flavor flavor NOT NULL,
    price numeric(10, 2) NOT NULL,
    gluten_free boolean NOT NULL,
    bakery_id integer NOT NULL REFERENCES bakery (id)
);
"#;

# fn main() -> Result<(), Box<dyn std::error::Error>> {
let output = entities_from_sql(DDL, EntityWriterOptions::default())?;

let names: Vec<&str> = output.files.iter().map(|file| file.name.as_str()).collect();
assert_eq!(names, ["bakery.rs", "cake.rs", "mod.rs", "prelude.rs", "pgorm_active_enums.rs"]);

let cake = &output.files[1].content;
assert!(cake.starts_with("//! `pgorm` Entity, @generated by pgorm-codegen"));
assert!(cake.contains("# [pgorm (table_name = \"cake\")] pub struct Model"));
assert!(cake.contains("pub flavor : Flavor"));
assert!(cake.contains(
    "# [pgorm (column_type = ColumnType :: Decimal (Some ((10u32 , 2u32))))] pub price : Decimal"
));
assert!(cake.contains(
    "# [pgorm (belongs_to = super :: bakery :: Entity , from = Column :: BakeryId , to = super :: bakery :: Column :: Id ,)] Bakery"
));

let bakery = &output.files[0].content;
assert!(bakery.contains("# [pgorm (has_many = super :: cake :: Entity)] Cake"));
# Ok(())
# }
```

The files are:

- one `<table>.rs` per table, holding its `Model` and `Relation`;
- `mod.rs`, declaring each module (`lib.rs` instead when the `lib` option is
  set, for a crate of entities alone);
- `prelude.rs`, which re-exports each `Entity` under the table's name in
  CamelCase (`Cake` for `cake::Entity`);
- `pgorm_active_enums.rs`, one [`ActiveEnum`](derive@crate::ActiveEnum) per
  enum type the tables use, when they use any;
- `pgorm_range_types.rs`, one [`CreatedRange`](derive@crate::CreatedRange)
  newtype per range type the schema creates, when a column uses one.

Each file opens with a line saying it was generated. The content is token
text, as the assertions above show; run rustfmt over the files once they are
written.

The files say only what the derives would not. A relation is written on both
sides, `belongs_to` where the foreign key is and `has_many` on the table it
points to; the `Related` impls one relation implies are left to the
`Relation` derive, and only a path through a junction table gets a `Related`
impl of its own. An enum's `enum_name` and `string_value` appear only where
the database's names are not the snake_case the derive would choose.

## Writing the files

A small binary, or a build script, reads the schema, generates, and writes
each file:

```rust
use pgorm_codegen::{EntityWriterOptions, entities_from_sql};

fn generate(schema: &std::path::Path, out: &std::path::Path) -> Result<(), Box<dyn std::error::Error>> {
    let ddl = std::fs::read_to_string(schema)?;
    let output = entities_from_sql(&ddl, EntityWriterOptions::default())?;
    std::fs::create_dir_all(out)?;
    for file in output.files {
        std::fs::write(out.join(&file.name), file.content)?;
    }
    Ok(())
}

# fn main() -> Result<(), Box<dyn std::error::Error>> {
# let dir = std::env::temp_dir().join(pgorm_test_support::scoped_name("guide_codegen_write"));
# std::fs::create_dir_all(&dir)?;
# let schema = dir.join("schema.sql");
# std::fs::write(&schema, "CREATE TABLE bakery (id serial PRIMARY KEY, name varchar NOT NULL);")?;
# let out = dir.join("entities");
generate(&schema, &out)?;
assert!(out.join("bakery.rs").exists());
assert!(out.join("mod.rs").exists());
# std::fs::remove_dir_all(&dir)?;
# Ok(())
# }
```

Each run writes every file afresh, `mod.rs` and `prelude.rs` included, so
keep hand-written code out of the generated directory, or generate once and
edit the files by hand from then on.

## Options

`EntityWriterOptions` names every option, and its `Default` asks for none:

| Field | What it does |
| --- | --- |
| `with_serde` | derive serde's `Serialize`, `Deserialize`, or both (`WithSerde::Both`) on each `Model` |
| `serde_skip_deserializing_primary_key` | with `Deserialize`, skip the key when deserializing, for a model built from client input |
| `serde_skip_hidden_column` | with serde, skip in both directions each column whose name starts with `_` |
| `with_copy_enums` | derive `Copy` on each generated enum |
| `lib` | write `lib.rs` rather than `mod.rs` |
| `schema_name` | the schema an unqualified table is in; a table the DDL qualifies keeps its own |
| `model_extra_derives`, `model_extra_attributes` | further derives and attributes for each `Model` |
| `enum_extra_derives`, `enum_extra_attributes` | the same for each enum |
| `unkinded_disjoint` | table sets to read as an unkinded [disjoint enum](crate::guide::disjoint) |

```rust
use pgorm_codegen::{EntityWriterOptions, WithSerde, entities_from_sql};

# fn main() -> Result<(), Box<dyn std::error::Error>> {
let ddl = "CREATE TABLE customer (id serial PRIMARY KEY, email varchar NOT NULL UNIQUE, notes text);";
let output = entities_from_sql(
    ddl,
    EntityWriterOptions {
        with_serde: WithSerde::Both,
        lib: true,
        model_extra_derives: vec!["Hash".to_owned()],
        ..Default::default()
    },
)?;

let customer = &output.files[0].content;
assert!(customer.contains("use serde :: { Deserialize , Serialize } ;"));
assert!(customer.contains(
    "# [derive (Clone , Debug , PartialEq , Entity , Eq , Serialize , Deserialize , Hash)]"
));
assert!(customer.contains("# [pgorm (unique)] pub email : String"));
assert!(customer.contains("pub notes : Option < String >"));
assert!(output.files.iter().any(|file| file.name == "lib.rs"));
# Ok(())
# }
```

An option that is not valid Rust, such as a derive written `"Hash("`, is
refused before the schema is read.

## Types

Each column becomes a field of the type [Entities](crate::guide::entities) maps to
it, the other way round: `varchar` and `text` become `String`, `integer`
`i32`, `numeric` `Decimal`, `timestamptz` `DateTimeWithTimeZone`, a nullable
column an `Option`, an array a `Vec`, an enum its generated `ActiveEnum`, a
range [`Range`](crate::pgorm_query::Range), and a domain its base's type with
the domain named in `column_type`. Where the field's type would not give the
column's own type back, the file states a `column_type`, as for the price's
`numeric(10, 2)` above. A `Model` with a floating-point column does not derive
`Eq`.

## What it refuses

The DDL is read in full or not at all. What the entity model can hold is
read: `CREATE TABLE` with its columns, keys, foreign keys, defaults and
generation expressions; `ALTER TABLE` adding a column or a constraint to a
table the text creates; enum and range types; domains; indexes; schemas; and
comments on tables and columns. Anything else, from a `CREATE TRIGGER` to a
`CHECK` on a column, is refused with a `TransformError` naming it and the
statement it is in, never skipped. The error displays that message, so a
program prints it as it is.

So the output of `pg_dump --schema-only` is refused: it opens with `SET`s,
changes owners, and adds its keys with `ALTER TABLE` after the tables. Write
the schema as `CREATE` statements, each table's keys inside it.

```rust
use pgorm_codegen::{EntityWriterOptions, entities_from_sql};

# fn main() {
let dumped = "SET statement_timeout = 0;\nCREATE TABLE bakery (id serial PRIMARY KEY);";
let Err(error) = entities_from_sql(dumped, EntityWriterOptions::default()) else {
    panic!("a pg_dump preamble is refused");
};
assert_eq!(error.to_string(), "unsupported DDL: SET at statement 1");

let geometry = "CREATE TABLE delivery (id serial PRIMARY KEY, drop_off point NOT NULL);";
let Err(error) = entities_from_sql(geometry, EntityWriterOptions::default()) else {
    panic!("a type the entity model lacks is refused");
};
assert_eq!(
    error.to_string(),
    "unsupported DDL: type `point` on column `delivery`.`drop_off` at statement 1"
);
# }
```

## From entities and back

[Schema generation](crate::guide::schema) turns an entity into DDL, and codegen
turns DDL into an entity, so each undoes the other. The DDL pgorm writes for
the bakery's entities generates the bakery's modules again:

```rust
use pgorm::Schema;
use pgorm_codegen::{EntityWriterOptions, entities_from_sql};
use pgorm_guide_support::{bakery, cake};

# fn main() -> Result<(), Box<dyn std::error::Error>> {
let schema = Schema::new();
let mut ddl: Vec<String> = schema
    .create_enum_from_entity(cake::Entity)
    .iter()
    .map(|create| create.to_string())
    .collect();
ddl.push(schema.create_table_from_entity(bakery::Entity)?.to_string());
ddl.push(schema.create_table_from_entity(cake::Entity)?.to_string());

let output = entities_from_sql(&ddl.join(";\n"), EntityWriterOptions::default())?;
let names: Vec<&str> = output.files.iter().map(|file| file.name.as_str()).collect();
assert_eq!(names, ["bakery.rs", "cake.rs", "mod.rs", "prelude.rs", "pgorm_active_enums.rs"]);
assert!(output.files[4].content.contains("pub enum Flavor { Chocolate , Vanilla , Lemon , Carrot , }"));
# Ok(())
# }
```

## Disjoint enums and one-of references

The tables [`Schema::create_disjoint`](crate::Schema::create_disjoint) writes
for a [disjoint enum](crate::guide::disjoint) generate as that enum again: the base's
module holds the `#[derive(Disjoint)]` enum beside the base's `Model`, and
each kind's table is an entity of its own. A table's `CHECK` that a
[one-of reference](crate::guide::one_of) writes generates its `#[derive(OneOf)]`
enum the same way.

```rust
mod vehicle {
    use pgorm::entity::prelude::*;

    #[derive(Clone, Debug, PartialEq, Entity)]
    #[pgorm(table_name = "vehicle")]
    pub struct Model {
        #[pgorm(primary_key)]
        pub id: i32,
        pub kind: super::VehicleKind,
        pub name: String,
    }

    #[derive(Copy, Clone, Debug, Relation)]
    pub enum Relation {}
}

mod van {
    use pgorm::entity::prelude::*;

    #[derive(Clone, Debug, PartialEq, Entity)]
    #[pgorm(table_name = "van")]
    pub struct Model {
        #[pgorm(primary_key, auto_increment = false)]
        pub id: i32,
        pub cakes_per_trip: i32,
    }

    #[derive(Copy, Clone, Debug, Relation)]
    pub enum Relation {}
}

use pgorm::entity::prelude::*;

/// The bakery's delivery vehicles: vans carry a load, bikes carry nothing
/// worth recording.
#[derive(Clone, Debug, PartialEq, Disjoint)]
#[pgorm(base = vehicle::Entity)]
pub enum Vehicle {
    Van(van::Model),
    Bike,
}

# fn main() -> Result<(), Box<dyn std::error::Error>> {
use pgorm_codegen::{EntityWriterOptions, entities_from_sql};

let ddl: Vec<String> = pgorm::Schema::new()
    .create_disjoint::<Vehicle>()?
    .iter()
    .map(|statement| statement.to_string())
    .collect();
let output = entities_from_sql(&ddl.join(";\n"), EntityWriterOptions::default())?;

let vehicle = output
    .files
    .iter()
    .find(|file| file.name == "vehicle.rs")
    .expect("the base's module");
assert!(vehicle.content.contains("Disjoint"));
assert!(vehicle.content.contains("Van (super :: van :: Model)"));
assert!(output.files.iter().any(|file| file.name == "van.rs"));
# Ok(())
# }
```

A set of tables with no kind column, whose base rows' kinds are known only by
which kind table has a row for them, has no DDL that says so. The
`unkinded_disjoint` option names such a set, its base, its kind tables and
its unit kind, and codegen generates it as an `unkinded`, read-only disjoint
enum.

## The stages

`entities_from_sql` runs three public stages, which can also be called one at
a time: `parse_schema` reads the text into pgorm-query
[`TableCreateStatement`](crate::pgorm_query::TableCreateStatement)s,
`EntityTransformer::transform` builds the entities from them and an
`EntityWriterContext` made from the options, and `EntityWriter::generate`
writes the files. Statements built in code with the [query
builder](crate::guide::query_builder)'s DDL generate the same way as text.

```rust
use pgorm_codegen::parse_schema;

# fn main() -> Result<(), Box<dyn std::error::Error>> {
let tables = parse_schema("CREATE TABLE bakery (id serial PRIMARY KEY, name varchar NOT NULL);")?;
assert_eq!(tables.len(), 1);
assert_eq!(
    tables[0].to_string(),
    r#"CREATE TABLE "bakery" ( "id" serial NOT NULL, "name" varchar NOT NULL, PRIMARY KEY ("id") )"#
);
# Ok(())
# }
```
